# PC 端手势遥控

用电脑摄像头识别手势，通过蓝牙串口控制小车。基于 MediaPipe 官方
预训练模型，**不自行采集数据集、不训练模型**。

| 手势 | 小车动作 | 发送字节 |
| --- | --- | --- |
| 握拳 `Closed_Fist` | 左转 | `0x03` |
| 张开手掌 `Open_Palm` | 右转 | `0x04` |
| 无手 / 认不出 / 多只手 / 手势切换中 | 停车 | `0x00` |

---

## 1. 设计原则

手势识别天然是不稳定的：同一个手势在不同帧上置信度会波动，手一晃就会
掉帧，光线一变就可能认不出来。如果逐帧把分类结果直接变成转向命令，
小车会疯狂抖动，而且一旦识别流程卡死，上一条转向命令会**一直生效**。

因此本实现遵循两条原则：

1. **不逐帧直接映射。** 只有同一个有效手势**持续稳定**超过设定时间
   （默认 200ms）才允许转向；切换过程中一律停车。
2. **失效即停车。** 任何不确定的情况 —— 无手、置信度不足、出现了不支持
   的手势、多只手导致歧义、识别流程停止更新 —— 结果都是停车。
   停车是默认状态，转向是需要被"证明"的例外。

配合 STM32 端的 500ms 心跳超时保护，电脑崩溃或蓝牙断开时小车也会自动停下。

## 2. 系统组成

```
  摄像头 ──► MediaPipe 手势识别 ──► 决策层 ──► 串口 ──► 蓝牙 ──► STM32
             recognizer.py        gesture_logic.py  serial_link.py
                    │                   │
                    └─────► 显示层 ◄─────┘
                           display.py
```

### PC 端模块

| 文件 | 职责 |
| --- | --- |
| `recognizer.py` | MediaPipe 封装。一帧图像 → 手部关键点 + 手势类别 + 置信度 |
| `gesture_logic.py` | 决策层。稳定性判定、手势→指令映射。**纯逻辑、无外部依赖、可单测** |
| `serial_link.py` | 串口层。端口枚举与甄别、连接、按心跳发送、出错即断开 |
| `display.py` | 画面叠加：手部关键点连线、手势与置信度、控制意图、通信状态 |
| `app.py` | 预览模式与实际控制共用的主循环 |
| `console.py` | 中文控制台编码保险（见 [TROUBLESHOOTING.md](TROUBLESHOOTING.md) 第 5 节）|

`recognizer.py` 与 `gesture_logic.py` 的职责分离是刻意的：决策逻辑不依赖
摄像头和 MediaPipe，因此可以在没有硬件的情况下完整测试。

### STM32 端配合

PC 端需要 STM32 端支持手势模式与心跳超时（见仓库根 README 的
「手势遥控（STM32 端行为）」一节）。**未烧录该固件时，手势指令不会生效**
——STM32 不认识 `0x10` / `0x11`。

## 3. 环境准备

需要 Python 3.9 以上（实测 3.12）。建议用独立的虚拟环境：

```bash
conda create -n car-gesture python=3.12 -y
conda activate car-gesture
cd pc_controller
pip install -r requirements.txt
```

安装后自检：

```bash
python check_env.py             # 依赖、模型、串口
python check_env.py --cameras   # 额外逐个探测摄像头
```

> **必须用 `opencv-contrib-python`，不要装 `opencv-python`。**
> mediapipe 依赖前者；两个都装会同时提供 `cv2` 包并互相覆盖。
> `check_env.py` 会检测这一点。详见 [TROUBLESHOOTING.md](TROUBLESHOOTING.md) 第 3 节。

## 5. 使用方法

### 5.1 快速开始

Windows 下可直接双击启动器：

| 文件 | 作用 |
| --- | --- |
| `run_preview.bat` | **预览模式**。只开摄像头，不连小车、不发送任何指令 |
| `run_control.bat` | **实际控制**。摄像头 + 蓝牙，真正驱动小车 |

启动器内预设 `--port auto --min-score 0.50`，可自行编辑。
其他平台或需要更多参数时走命令行。

### 5.2 命令行

```bash
# 预览模式（不加载 pyserial，从根上避免误发指令）
python gesture_preview.py

# 实际控制
python gesture_control.py --port auto --min-score 0.50

# 查看串口
python gesture_control.py --list-ports
```

预览模式这个入口**连 pyserial 都不 import**，因此不可能向小车发送任何数据。

### 5.3 建议的验证顺序

分三步，每步单独确认，出问题好定位。

**第一步：只验手势识别（不连小车）**

```bash
python gesture_preview.py
```

画面上会显示：摄像头图像与手部关键点、原始手势类别及置信度、
最终控制意图、通信状态、FPS。按 `q` 或 `ESC` 退出。

要确认的现象：

1. 握拳时"手势"一行显示 `Closed_Fist`，置信度合理
2. 握拳**持续约 200ms 后**"意图"才变成左转；举一下马上放下不会转
3. 手掌张开 → 右转，同样需要稳定 200ms
4. 手离开画面 → 立刻变回停车
5. 左转与右转之间来回切换 → 一直显示停车

**第二步：只验串口（不涉及摄像头）**

```bash
python serial_test.py --list
python serial_test.py --port auto
```

按键直接发送原始字节，用来把"串口链路的问题"和"手势识别的问题"分开。
**第一次务必把车轮架空。**

**第三步：联调**

```bash
python gesture_control.py --port auto --min-score 0.50
```

启动流程：打开串口 → 发送 `0x10` 进入手势模式 → 发送 `0x00` 停车 →
之后按心跳间隔持续发送当前意图。**连接后小车是停着的，不会自己开始转向。**

按 `q` / `ESC` 退出时会尽力发送「停车 + 退出模式」再释放串口；
串口断开后按 `r` 可尝试重连。

### 5.4 参数调优

屏幕上跳动的置信度无法用来定阈值，因此提供了记录 + 统计两件工具：

```bash
python gesture_preview.py --log-scores scores.csv
```

按顺序做，每段之间把手移开画面停一下：

| 顺序 | 做什么 | 时长 |
| --- | --- | --- |
| 1 | 手完全不进画面 | 约 5 秒 |
| 2 | 握拳，保持不动 | 约 10 秒 |
| 3 | 张开手掌，保持不动 | 约 10 秒 |
| 4 | 随便做点别的手势（比 V、竖大拇指）| 约 5 秒 |

退出后：

```bash
python analyze_scores.py scores.csv
```

输出每个类别的置信度分布，以及不同阈值下的**帧通过率**，并据此给出
`--min-score` 的建议值。"帧通过率"是关键指标：阈值定得过高，正常做手势
时会有相当比例的帧被判无效，表现为手势中途断掉、小车一顿一顿地转/停。

记录的是**原始**分类结果，不受 `--min-score` 影响，可以反复用同一份数据
试不同阈值。

## 6. 手势决策逻辑

### 6.1 稳定判定

用**经过的毫秒数**（`time.monotonic()`）判断，不看帧数：

```
候选手势 = 本帧类别，当且仅当该类别受支持 且 置信度 >= min_score
否则候选手势 = 无

若候选手势与上次不同 → 重新计时
若候选手势连续保持 >= hold_ms → 允许转向
否则 → 停车
```

这样摄像头帧率高低、偶尔掉帧都不会改变判定结果。切换手势时计时重置，
切换过程中一律停车。

### 6.2 停车条件

以下情况**全部**输出停车：

| 情况 | 说明 |
| --- | --- |
| 画面中无手 | |
| 置信度低于阈值 | 不信任边缘识别 |
| 出现了不支持的手势 | 只认握拳与张开手掌，其余一律停车 |
| 检测到多只手 | 可能给出互相矛盾的结论，判为有歧义 |
| 手势切换尚未确认 | 稳定时间未满 |
| **识别流程停止更新** | 超过 `stale_ms` 没有新结果 |

最后一条容易被忽略：摄像头拔掉或识别线程卡死时，"没有新结果"和
"画面里没有手"看起来是一样的。实现上用 `last_frame_ts` 把两者区分开
（便于显示不同原因），但**两者都输出停车** —— 关键在于绝不能让上一条
转向命令继续生效。

## 7. 通信协议

### 7.1 指令字节

| 字节 | 含义 |
| --- | --- |
| `0x00` | 停车 |
| `0x03` | 左转（复用原有手机遥控指令）|
| `0x04` | 右转（复用原有手机遥控指令）|
| `0x10` | 进入手势遥控模式 |
| `0x11` | 退出手势遥控模式 |

`0x10` / `0x11` 是新增的模式控制字节，原本未被占用，**不影响手机 App
原有的 `0x00`~`0x06`**。发送的是原始字节，不是字符串 `"0x03"`。

### 7.2 心跳与超时

PC 端约每 **100ms** 重发一次当前指令（意图不变也照发，STM32 靠它判断
电脑是否还活着）；意图发生变化时立即发送，不受心跳间隔限制。

STM32 端超过 **500ms** 未收到有效控制帧则强制停车。两道保护互相独立：

- PC 端：串口发送异常 → 立即进入断开状态，停止一切运动控制
- STM32 端：收不到心跳 → 强制停车（不依赖 PC 是否还活着）

### 7.3 退出行为

正常退出时依次发送 `0x00`（停车）与 `0x11`（退出模式），再释放串口。
每一步单独捕获异常 —— 蓝牙已掉线时不能因为发不出去就连端口都不关。

## 8. 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--camera` | `0` | 摄像头编号。内置一般为 0，外接的试 1、2 |
| `--width` / `--height` | 640 / 480 | 采集分辨率（请求值，实际以摄像头为准）|
| `--backend` | `auto` | 采集后端，`auto` = dshow → msmf → any |
| `--no-mirror` | 关 | 默认左右镜像（符合照镜子的直觉）|
| `--hold-ms` | `200` | 同一手势需持续多少毫秒才允许转向 |
| `--min-score` | `0.60` | 置信度阈值。**建议按第 5.4 节实测调整** |
| `--stale-ms` | `300` | 多久没有新识别结果按输入过期处理（停车）|
| `--num-hands` | `2` | 最多检测几只手。设 2 是为了能发现"多只手有歧义" |
| `--log-scores FILE` | 关 | 记录每帧原始手势与置信度到 CSV |
| `--port` | `auto` | 串口。`auto` = 自动甄别可用的蓝牙口 |
| `--baud` | `9600` | 必须与 STM32 一致 |
| `--heartbeat-ms` | `100` | 心跳间隔 |
| `--list-ports` | — | 列出串口后退出 |

### 实测调参结果

在同一台 640×480 内置摄像头上录制的 1896 帧数据：

| 类别 | 帧数 | 最低 | p05 | 中位 | p95 | 最高 |
| --- | --- | --- | --- | --- | --- | --- |
| `Closed_Fist` | 691 | 0.450 | 0.540 | 0.681 | 0.850 | 0.889 |
| `Open_Palm` | 635 | 0.498 | 0.542 | 0.667 | 0.720 | 0.737 |
| `Victory`（不参与判定）| 79 | 0.642 | 0.781 | 0.798 | 0.836 | 0.849 |

不同阈值下的帧通过率：

| 阈值 | `Closed_Fist` | `Open_Palm` |
| --- | --- | --- |
| 0.45 | 99.9% | 100% |
| **0.50** | **98.7%** | **99.7%** |
| 0.55 | 92.9% | 94.5% |
| 0.60（代码默认）| 82.9% | 84.7% |
| 0.70 | 43.6% | 14.0% |

**结论**：该摄像头下应用 `--min-score 0.50`。代码默认值 0.60 在该设备上
会导致 15%~17% 的帧被判无效，表现为小车一顿一顿地转/停。
这说明阈值与具体摄像头、光照、距离强相关，**应针对自己的设备实测调整**，
而不是照搬默认值。

`--hold-ms` 保持默认 200ms 即可：实测握拳最长连续 11.4 秒、
张开手掌 11.1 秒，远大于判定时间。

## 10. 已知限制

- **只支持单手、两种手势。** 多只手按"有歧义"处理，直接停车。
- **不做手势扩展。** 添加新手势需要同时改 `GESTURE_TO_INTENT` 与
  STM32 端的指令映射。
- **转向指令只有左右转与停车**，没有前进/后退 —— 本版定位是方向控制。
- **性能数据来自 CPU 推理**（7.3 ms/帧）。真实摄像头 + 真实手势的端到端
  帧率还受摄像头自身帧率与画面刷新限制。
- **`--min-score` 与 `--hold-ms` 强依赖使用环境**，换摄像头/光照/距离后
  应重新实测。
